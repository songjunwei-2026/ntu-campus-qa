# 项目说明书

这份文档留给两种时候：半年后自己回来看，或者答辩、跟别人聊技术方案时照着讲。

操作层面（怎么启动、怎么补数据、坏了怎么办）在 `使用说明.md`。检索规则的具体参数在 `docs/RULES.md`。这份讲的是整件事的来龙去脉：它为什么长这样、中间踩了什么、哪些还没弄好。

---

## 一、它到底是什么

一个跑在本机的网页。输入「学生证丢了怎么办」，它给出补办流程，每个结论后面挂着 `[1]`，点开就是学校原文的那一段。

跟直接搜官网的区别在哪。这些文件散在教务处、学工处、后勤、保卫处等十几个站点上，你得自己翻、自己判断哪份管你。这个是先判断你问的是「规定」还是「地点」，把可能相关的几段捞出来，让模型只拿这几段话组织答案，答完把出处贴回去。捞不出来就明说没有，不猜。

现在的语料规模（2026-11-06 实测 `/api/status`）：

| | 数量 |
|---|---|
| 政策文件 | 612 份 |
| 切分后的段落 | 3180 段 |
| 正文字数 | 78.8 万 |
| 文件年份跨度 | 2011 – 2026 |
| 官网栏目抓取 | 263 篇 |
| 人工核实的事实条目 | 39 条 |
| 校内地点 | 42 个 |
| 归口部门 | 13 个 |
| 语料最后更新 | 2026-10-23 18:08 |

另外记了 1041 条没答上来的问题。这份 `misses.jsonl` 是整个项目里最有价值的数据——它告诉你真实的人在问什么、你的库缺什么，比任何自测题都准。

## 二、三分钟跑起来

```bash
cp config.example.json config.json     # 填 DeepSeek 的 key，不填也能跑
python server.py 8001
```

不用装依赖，纯标准库。只有在重新生成二维码时才要 `pip install qrcode`。

浏览器开 `http://127.0.0.1:8001`。或者直接双击 `start.bat` 或根目录那个中文名的「一键启动」。

不填 key 也能跑，只是退化成原文摘录，不做归纳。

## 三、一次提问走的路

```
你打一句话
   │
   ├─ 判断问的是地点还是规定 ──「在哪 / 怎么走 / 几楼」→ 走地图，不查文件
   │
   ├─ 拆句：一句话里有几个意图就拆几段，各自检索
   │
   ├─ 检索：二字切片 + BM25 + 六个系数，捞前若干段
   │
   ├─ 三层过滤
   │    ├─ 文书类型：问制度就别端公示名单、日程安排
   │    ├─ 适用对象：本科生问的事，不给博士招生办法
   │    └─ 专名缺口：语料里根本没见过这个词，不猜
   │
   ├─ 五道拒答闸，有一道过不去就不答
   │
   ├─ 模型生成（提示词 12 条约束）
   │
   └─ 引用回链 + 相关问
```

### 四个当时想明白的事

**1. 用字面检索，不用向量。**

这是最反直觉的一个选择。向量检索擅长「意思相近」，但校园政策问答真正难的不是这个。问「国家奖学金怎么评」和问「课程考核怎么算分」，两句话语义上都在谈成绩，向量会排得很近。真正决定该给哪份文件的是**这份文件管不管我**——适用对象、文书类型、发文年份。这是元数据问题，不是语义问题。

所以走 BM25 加规则过滤。字面匹配到「国家奖学金」这五个字，比语义上「都跟成绩有关」有用得多。

代价也有：同义词完全打不中。问「挂科」不会命中「不及格」。这是我认下的账。

**2. 宁缺勿假。**

答错一条的实际代价，比少答十条大得多。这些答案会直接告诉学生去哪个窗口、带什么材料、几号截止，写错一条人家真会跑空一趟。

所以拒答门槛设得偏严。副作用是有些本该答的也拒了，这个后面「还不行的」那一节里承认了。

**3. 引到句，不引到文件。**

一般 RAG 引到文档就完了。这个往下钻了两层：文档 → 段 → 句。因为政策文件动辄几千字，告诉人家「看这份文件第 3 条」等于没说。

**4. 语料分三层存。**

政策文件（`chunks.jsonl`）、官网通知（`web_chunks.jsonl`）、人工核实（`facts_chunks.jsonl`）分开。原因不一样：政策文件是权威的但滞后，官网通知新但零碎，人工核实的是那些官网压根没有的信息（图书馆几点关门、某办公室在几楼）。

分开存才能分别控制权重，也能一眼看出哪条是抓来的、哪条是我手填的。

## 四、踩过的问题，一个个说

这一节是重点。按发现顺序，不是按重要程度。

### 4.1 「更新文件库」是个假按钮

界面左下角原来有个按钮，点了弹一句「已更新」。我信了很久。

后来想验证一下，就在语料里插了一条假文件，点按钮，再查 `/api/status`——份数一点没变。再查代码，那个按钮从头到尾只做了一件事：`alert()`。后端根本没有重新读盘的方法。

改法是加一个 `POST /api/rebuild`，真的重建检索器、清空答案缓存，把增删的份数和耗时返回给前端。验证方式必须是这样：插入一条 → 数字从 612 变 613 → 恢复 → 变回 612。只看接口返回 200 什么都证明不了。

**这件事教我的**：按钮上有字，不代表它做了那件事。

### 4.2 加了 rebuild 接口，前端调它一直 404

接口写好了，前端 `fetch('/api/rebuild')` 报 404。

原因：`server.py` 里 `do_GET` 和 `do_POST` 两个方法分开写，我把新分支插进了 `do_GET`，而前端发的是 POST。Python 的 `BaseHTTPRequestHandler` 不会提示你「这个方法里没这个路由」，它就是 404。

改法是把分支挪到 `do_POST`。

**教我的**：自己写的路由分发没有框架兜底，方法和路径对不上时，报出来的错跟「路径不存在」一模一样。

### 4.3 接口突然返回 `http 000`

前端控制台看到的是 `http 000`，看着像端口没起来、或者服务崩了。

实际是 `server.py` 顶部漏了 `import time`，但有个统计函数在用 `time.time()`。一调用就抛 `NameError`，异常没被捕获，连接直接被掐断。curl 那边看到的就是 000——连 HTTP 状态码都没有，因为响应根本没发出来。

**教我的**：000 不是「没连上」，是「连上了但对面没说一句话就断了」。这两个要分开查。

### 4.4 改了代码，跑起来还是旧行为

这条最耗时间。

改完 `server.py` 重启，行为没变。反复检查代码，确实改了。最后用 `Get-CimInstance Win32_Process -Filter "Name='python.exe'"` 一看——同时有三个 `python server.py 8001` 在跑。

Windows 的 socket 默认带 `SO_REUSEADDR`，同一个端口能被多个进程绑上，最后一个不会报错。请求进来时谁接是不确定的，多数时候是最老的那个接——于是你改的代码在跑，但用户（你自己）请求打到了另一个进程。

**教我的**：改完代码行为不变，先数进程，别先怀疑代码。现在每次重启前都先查一遍。

### 4.5 「更新文件库」之后官网语料还是不更新

`_cache_state_now()` 这个函数决定缓存什么时候失效，它拼了一个指纹，由几份语料的修改时间组成。

我漏了 `web_chunks.jsonl`。所以重新抓了官网内容、文件确实变了，但指纹没变，缓存认为「一切照旧」，继续返回旧答案。

**教我的**：凡是「拿一组文件的状态算指纹」的函数，加新文件时最容易漏。现在这个函数里三份语料都写在一起，加文件得同时改这里。

### 4.6 左下角显示的「语料更新于」是打开网页的时间

那个位置写着「语料更新于 10月23日 18:08」，看着挺专业。实际上取的是 `new Date()`——你刷新页面的那一刻。

真要用得从后端给。`/api/status` 加了 `corpus_mtime`，取三份语料里最大的修改时间。

改完又踩一个坑：我用 `cp` 覆盖了语料文件，`cp` 会把修改时间改成当前时间，于是显示变成「今天」。得用 `os.utime()` 把它拨回去：

```python
os.utime(path, (1792750105, 1792750105))
```

**教我的**：文件修改时间是可以被人为改动的，一旦它变成展示给用户的信息，复制文件就会污染它。

### 4.7 一键启动脚本，换台机器就打不开

`E:\desktop\ntu` 这个路径在两个 `.bat` 里写死了。我把项目搬到 `E:\desktop\agent小项目\网站\ntu`，脚本立刻报 `Launcher not found`。

改法是用 `%~dp0`，它表示「这个 .bat 自己所在的目录」，跟谁把它搬去哪没关系。

但这里还埋着一个更麻烦的：原来的脚本是 `call launch.bat`，而 `launch.bat` 写在 `.gitignore` 里。也就是说本地能跑，推到 GitHub 上的版本别人 clone 下来是跑不起来的——少一个被调用的文件。

**教我的**：一个文件能不能独立运行，要看它依赖的东西是不是也在仓库里。`.gitignore` 是个很容易忘记的断点。

### 4.8 外部验收打了 59 分

2026-10-29 找人（Codex）从外部审了一遍，59/100。这份报告现在还在 `_archive/` 里。

被打回来的东西分两类，第二类更难看：

**真缺陷**：缓存命中时只发一个 `final` 事件，中间没有 `delta`——被判成假流式；「食堂承包商是谁」被地点列表兜底成了「食堂在哪」；正文对比度 3.29:1 和 2.26:1，低于无障碍标准的 4.5。

**判据失真**：`README` 写着 20/20，实测 11/20。原因是回归脚本的判据太松——只要返回了引用就算过，哪怕首条引用是「获奖名单公示」。

第二类才是真问题。**测试全绿但产品是坏的**，这比测试报红危险得多，因为你会以为自己没问题。

修完之后问答层从 15 提到 19，检索层从 11 提到 15。

**教我的**：写测试的时候要问一句「这条断言，产品坏掉的时候它会不会还是绿的」。会绿的断言等于没写。

### 4.9 拒答的两头都错

一开始 `_offscope` 是个二值开关：整个问题判成「超范围」或「不超范围」。

问题在于很多问题是混着的。本科生问「补考没过重修咋收费，会影响保研不」——前半句是本科生教务，后半句牵扯到研究生推免。一刀切成超范围，前半句就白问了；一刀切成不超范围，又会把博士招生办法端出来。

改成逐条比对适用对象，每份候选文件单独判断管不管这个提问者。

还有个漏洞：一句话里如果有多个意图，代码会拆成子句分别检索。拆出来的子句没走文书类型和适用对象这两道过滤——因为过滤逻辑写在外层。等于说，一个复合问句可以绕过所有过滤。

**教我的**：分流、拆句、重试这类「再来一遍」的路径，最容易被漏掉的是原来那层过滤。

### 4.10 检索层还剩 5 条答错文件

问「国家奖学金评审办法」，首条给《课程考核管理办法》。问「转专业」，给《学籍管理规定》。

同一个模式：给的是一份「相邻主题」的文件——都跟成绩、学籍有关，字面上有不少词能对上，但不是要问的那件事。

这 5 条在问答层已经全部拒答了，差别在 `/api/keyword` 这条链路没有语义判断能力，纯靠字面。阈值调不动：调高会把本来对的那 15 条一起调掉。

真要治，得上条款级索引（现在是段落级，一段几百字，粒度太粗）或者加个重排模型。这是我知道但还没做的事。

### 4.11 相关问会推出不相关的题

答完「宿舍能用多大功率的电器」，下面推了两条：「宿舍能换吗」勉强算，第二条「学生证丢了怎么补办」跟宿舍用电毫无关系。

查了代码，原因在 B 表补位：`related.py` 里有一张每个话题族 3–5 道的保底题池，权重 0.2，作用是把推荐条数凑到 3–4 条。冷门话题凑不满，补位题就顶上来，很容易跳脱。

现在的约束是最多只带 1 条补位题。还不够，理想做法是冷门话题就只推 1–2 条，宁可少推也不凑数。

另外还有两个早先修掉的毛病：一是推了跟刚问的几乎一样的问题（加了相似度过滤，超过 0.55 不要）；二是学生问学生的事，推了《教职工××办法》（加了教职工文件过滤）。

维护入口是 `python related.py --check`，跑 67 道题，现在 0 失败。

### 4.12 把语料放进公开仓库之前，先扫了一遍

要往 public 仓库推 7.6 MB 语料，推之前扫了一次手机号、身份证、邮箱。

第一遍扫出 201 处，吓一跳。仔细看上下文，`17601110201`、`17176011101`、`170101101001`——这些是公文里的**编码示例**，年份 17 打头，被正则当成了手机号。

排除 17 开头剩 179 处，去重后 65 个。看上下文：24 小时报警电话、各校区驻点老师、部门值班手机。全是公文里本来就写给全校看的公务联系方式，原件挂在官网。

身份证 0 个，学生个人号码 0 个。这才推。

**教我的**：正则扫出来的数字要先看上下文再下结论。真要命的东西，往往长得不像。

## 五、怎么确认它没坏

改完代码至少要跑一个，改过检索或语料就跑前两个。

| 命令 | 耗时 | 看什么 | 正常值 |
|---|---|---|---|
| `python test_rules.py` | 1 秒 | 28 条拦截规则还成立吗 | 28/28 |
| `python tools/regress.py` | 秒级 | 检索层：首条文件对不对口 | 15/20 |
| `python tools/regress.py --ask` | 每题一次模型调用 | 问答层：首条引用对不对口 | 19/20 |
| `python tools/regress.py --related` | 几十秒 | 相关问：重复吗、推刚问过的吗、带出处吗 | 5/5 |
| `python eval.py` | 2 秒 | 另一套日常问法 | 18/20 |

当前状态（2026-11-06 实测）：

- 检索层 15/20
- 问答层 19/20，其中 C5 那条（「补考没过重修咋收费 会影响保研不」）会摆动，有时候 18/20，跟新功能无关，用 `git stash` 对照过了
- 拒答层 5/5
- 首页 10 条示例 10/10
- 相关问 5/5，深测把推荐的 16 道题真的又挨个问了一遍，全部能答且有引用
- 未缓存问题端到端 1.9–1.95 秒（`deepseek-flash`）；缓存命中 0.01 秒

分数不是越高越好，是**别掉**。掉分说明刚改的东西碰坏了别的。

## 六、现在还不行的

写在这一节的东西，别人问起来主动说，比被问出来强。

1. **检索层 5 条答错文件**。见 4.10，需要条款级索引或重排模型，不是调阈值能解决的。
2. **同义词打不中**。问「挂科」不命中「不及格」，问「退学」可能命中「休学」。字面检索的固有代价。
3. **语料有缺口**。研究生出国交流、校历调课、国家奖学金评审办法，全库没有对应文件。这几类问题现在是稳定拒答。
4. **校级文件被标成发文部门**。挂在研究生院站点的校级文件会带上 `dept=研究生院`，可能误导本科生。
5. **只有本机**。`127.0.0.1:8001`，没做公网部署。同一个 WiFi 下手机能访问（`start_lan.cmd`），出了校园网就不行。
6. **只记答不上的问题**。没有全量提问日志，所以没法按真实频次重排首页示例。
7. **示例题里有一条该换**。「毕业要修满多少学分」能返回文件，但首条是《参加国（境）外交流项目学分认定办法》——语料里根本没有毕业学分规定，这条示例等于在暴露短板。换成一条库里有把握的题，比留着它好。

## 七、如果重做一次

按优先级：

1. **先写评测，再写功能**。这次是反过来做的，先堆功能再补测试，结果测试判据偷懒，59 分那次吃了大亏。
2. **语料层做条款级切分**。现在按几百字切段，一段里可能混着好几条。切成「第 X 条」粒度，引用能精确到条款，误召回也会少。
3. **全量记录提问**。哪怕只是本地 jsonl，攒两个月就能知道真实问题分布，比拍脑袋设计示例强。
4. **相关问改成宁少不凑**。冷门话题推 1 条准确的，比推 4 条凑数的强。
5. **别用「假按钮」**。要么不做，要么真做。界面上的每个按钮都得有个测试证明它真的干了那件事。
