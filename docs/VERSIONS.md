# 版本对照

这个仓库里同时放着几个"版本"，但它们**不是靠复制目录区分的，而是靠 git 标签**。

复制一份目录出来当"备用版"是看着安心、实际会烂的做法：第二份代码从复制那秒起就开始过期，
半年后没人记得哪份是活的，改 bug 改到废弃的那份上，两边的引用和语料还会悄悄对不上。
git 本来就存着每个版本，缺的只是**给它们起名字**。

## 取出任意一版

```bash
# 只看不改：把旧版代码临时放到另一个目录（推荐，主目录不受影响）
git worktree add ../ntu-v0 v0-init

# 或者看一眼某个文件在旧版里长什么样
git show v0-init:server.py | head -40

# 对比两个版本改了什么
git diff v0-init..v1-audit --stat
```

用完 `git worktree remove ../ntu-v0` 清掉即可。

## 每一版发生了什么

**v0-init → v1-audit**（做的事最多）
三栏界面、条款检索、校园地图、多意图拆句、弱相关拒答、年份对齐、真流式、引用折叠。
这一阶段的问题不是"功能没有"，而是**答得对不对没人验证过**——

**v1-audit（59 分）暴露的两类问题**

| 类型 | 具体表现 |
|---|---|
| 真缺陷 | 缓存命中时只发一个 `final`（判成假流式）；地点兜底把"食堂承包商是谁"答成"食堂在哪"；正文对比度 3.29:1 / 2.26:1 低于 4.5 |
| 判据失真 | `regress.py` 问答层在首条引用是"获奖名单公示"时仍判 PASS；README 宣称 20/20，实测 11/20 |

**v1-audit → 当前**（`4d316ba` → `4f1894b`）
按"文书类型 + 适用对象"两层过滤重修了拒答，并把两条链路的排序统一：

| 改动 | 影响 |
|---|---|
| 缓存分支补 `meta/delta/final` | 任何按协议解析的客户端都能看到流式 |
| 标题二字命中优先排序 | 问"转专页"时不再把《学籍管理规定》顶到首位 |
| `_offscope` 从二值开关改成逐条比对 | 本科生问"影响保研"不再引到博士招生办法 |
| 提示词加"禁止反向推断" | 语料没有评审办法时不再答"未把不及格列为排除项" |
| 回归期望修正 2 处 | `D3` 三份语料 0 篇，应拒答；`B5` 放假通知在 `web_chunks` 里，恢复应命中 |

数字变化：问答层 15 → 19，检索层 11 → 15，`eval.py` 18/20 不变，首页 10 条示例 10/10。

**v1-audit → v2**（2026-11-02 / 11-06）

这一轮不加新检索能力，补的是「用起来缺的东西」：

| 改动 | 影响 |
|---|---|
| 答完推相关问（`related.py`） | 从命中的文件里推 2–4 条**已用同一链路验证过答得上来**的问法；推之前先跑一遍文书/对象过滤 |
| 新对话按钮 | 换个话题不用刷页面 |
| 「更新文件库」改真重建 | 原来只弹提示；现在走 `POST /api/rebuild`，返回真实增删份数与耗时 |
| 一键启动脚本入仓库 | 路径全改 `%~dp0`，整个文件夹搬走也不失效 |
| 侧栏显示改为语料修改时间 | 原先是打开页面的时间，`/api/status` 新加 `corpus_mtime` |
