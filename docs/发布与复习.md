# 发布与复习指南

这份文档解决两件事：**怎么把这个项目放到 GitHub**，以及**以后想回顾时怎么最快看懂它**。
日常使用网站（怎么打开、怎么问、怎么补数据）看 `使用说明.md`，不在这里重复。

---

## 一、发布到 GitHub（只做一次）

### 0. 发布前 60 秒检查

```bash
cd E:\desktop\ntu
git status --short                 # 应该什么都不输出（工作区干净）
git ls-files | wc -l               # 应该是 32 个文件
git ls-files | grep config         # 只应该出现 config.example.json
```

最后一条最关键。如果输出里出现 `config.json`，**停下**，那里面有你的 API Key，
一旦推上去就等于公开。先把它从暂存区拿掉：

```bash
git rm --cached config.json
git commit -m "chore: 移除误加的 config.json"
```

### 1. 用 GitHub Desktop 发布（推荐）

1. 打开 GitHub Desktop → 菜单 `File` → `Add Local Repository`
2. 目录选 `E:\desktop\ntu`，它会认出这是个 Git 仓库，点 `Add Repository`
3. 左上角 `Current Repository` 确认是 ntu，`Current Branch` 是 `main`
4. 点顶部 `Publish repository`
5. 弹出的框里填：
   - `Name`：`ntu-campus-qa`（英文，别用中文名）
   - `Description`：一句英文或中文都行，例如 `Campus policy QA with citation drill-down`
   - **`Keep this code private` 不要勾** —— 勾了复试就没法发链接
6. 点 `Publish repository`，等进度条走完

### 2. 命令行发布（不用 Desktop 的话）

先在网页上建一个**空仓库**：github.com → 右上角 `+` → `New repository`，
名字 `ntu-campus-qa`，**不要**勾 Add a README / .gitignore / license（勾了会和你本地的冲突）。

然后：

```bash
cd E:\desktop\ntu
git remote add origin https://github.com/你的用户名/ntu-campus-qa.git
git branch -M main
git push -u origin main
```

第一次 push 会要求登录，按提示走浏览器授权即可。

### 3. 发布后验证（3 条，1 分钟）

| 检查 | 期望 |
|---|---|
| 打开仓库首页 | README 正常渲染，标题是「通晓 · 南通大学校园政策问答」 |
| 翻一下文件列表 | 有 `server.py`、`rag.py`、`eval.py`、`docs/`；**没有** `config.json`、`corpus/chunks.jsonl`、`web/assets/campus.webp` |
| Settings 页往下翻 | 仓库是 Public（`Danger Zone` 上方能看到 Change visibility） |

三条都对，就算发布完成。

## 二、查看与复习

### 1. 只想在网页上看

| 想看什么 | 怎么做 |
|---|---|
| 某个文件的代码 | 仓库首页点文件名。英文文件名可以按 <kbd>t</kbd> 直接搜索 |
| 某次改动改了什么 | 顶部 `Commits` → 点一条 → 红的是删、绿的是加 |
| 一段代码的历史 | 打开文件 → 点行号左边 → `View git blame`，能看到每行是哪次提交写的 |
| 整个项目的决策过程 | `docs/CODEX_TASK.md`、`_2.md`、`_3.md` 就是当时分三批给 Codex 的任务单，等于一份开发日志 |

### 2. 本地跑起来（复习最常用）

双击 `E:\desktop\ntu\start.bat`，浏览器会自动打开 `http://127.0.0.1:8001`。
关掉黑色命令行窗口就是停止服务。

### 3. 三个体检命令

复习时不用全部跑，按需要挑：

| 命令 | 耗时 | 看什么 | 正常结果 |
|---|---|---|---|
| `python eval.py` | 约 2 秒 | 语料和检索有没有被改坏 | 检索层 20/20，答案层/拒答层显示「跳过」 |
| `python eval.py --llm` | 约 36 秒 | 三层全貌，要花钱（约 0.02 元） | 20/20、20/20、5/5 |
| `python test_rules.py` | 不到 1 秒 | 28 条拦截规则是否还成立 | 28/28 passed |

改过代码就至少跑第一个和第三个。`test_rules.py` 报红通常意味着：
你放宽了某条拦截规则，会有本该拒答的问题开始瞎答。

### 4. 想回到某个历史版本

```bash
git log --oneline              # 看所有提交和它们的短哈希
git checkout <短哈希>           # 只看，不改（会提示 detached HEAD，正常）
git checkout main              # 看完切回主线
```

看完一定要 `git checkout main` 回来，否则后面改的代码不在主线上。

## 三、已知限制（复试被问到时可以主动讲）

这些不是 bug，是刻意的取舍，讲出来比被问出来好：

1. **仓库不含语料和地图底图**。别人 clone 下来只有事实层 39 条，服务能起、页面能开，
   但绝大多数问题会答"没有收录"。完整版需要自己抓语料（`crawl_sites.py`）或人工录入
   （`add_fact.py`）。原因是学校官网内容的再分发需要授权，高德底图也不允许二次分发。
2. **不配 API Key 也能跑**，只是退化成"原文摘录"模式，不做归纳。
3. **地图页缺底图会留空白**，其余功能不受影响。

## 四、几个容易踩的坑

- 不要用 GitHub 网页「上传文件」的方式传整个目录，它**不读 `.gitignore`**，
  会把 `config.json` 和语料一起传上去。
- 不要用 `git add -f` 强推被忽略的文件，那是绕过保护。
- 换电脑 clone 下来后，要重新 `cp config.example.json config.json` 并填 Key，
  否则会退化成摘录模式（不报错，但答案质量明显下降）。
- 仓库里 `main` 是主线分支，别在 `master` 上改——本地曾经叫过 `master`，已改名为 `main`。
