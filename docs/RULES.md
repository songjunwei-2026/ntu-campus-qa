# 规则说明书

这份文档只回答一个问题：**这个站为什么这么答，凭什么拒答。**

代码会改，规则应当先被写下来——否则下一次调阈值时，没人知道原来那条线是为了堵哪个坑。
每条规则都标了落点（`文件:行号`），改动前请先读那段注释，那里通常写着它挡下的真实错例。

---

## 一、三条硬约束

这三条不是建议，是判定"能不能上线"的底线：

1. **有据可查**：答案里每个数字、期限、材料、地点，都必须能在引用原文里找到。找不到就说【未收录】。
2. **宁可拒答，不可硬凑**：拒答只是没帮上忙，编造会让人按错的规定去办事。
3. **答了就得说清出处**：引用要能定位到"哪份文件、第几段、第几句"，否则用户无法自查。

---

## 二、检索规则（`rag.py`）

### 2.1 分词：二字切片，不用词典分词

中文按 2-gram 切片（`rag.py:103`），去掉停用二字组合（`rag.py:94`）。
**为什么不用分词器**：用户会打错字。问"转专页"时词典分词认不出这个词，2-gram 能撞出"转专"。
这是"召回优先于精确"的选择：宁可多召回噪声，也不能让正确文件在第一关就出局。

### 2.2 打分链：BM25 × 六个系数

`rag.py:259-265`，依次相乘：

| 系数 | 作用 | 取值 |
|---|---|---|
| `_type_weight` | 条例/办法/规定 提权；通知/公告/公示 降权 | 1.10 / 0.80 / 1.0 |
| `_age_weight` | 越旧越降权，10 年后触底 | `max(0.75, 1 - 0.022×年差)` |
| `_scope_weight` | 问本科别让研究生文件抢前排 | 冲突时 0.65，单纯研究生文件 0.80 |
| `_title_boost` | 查询词命中标题越多越像"专门讲这件事" | `1 + 1.3×命中率` |
| `_ask_weight` | 问"条件/流程"时再压一档公告 | 0.62 |
| `_year_weight` | 问题写明年份时对齐 | 同年 1.60，每年偏 0.12，下限 0.55 |
| `SRC_W` | 官网抓取与 FAQ 的可信度折价 | web 0.90 / faq 0.92 |

**年份对齐是最容易被忽略的一条**：问"2026 年国庆放假调课"，2024 年的同类通知字符全中、年份全错。
不按年份压权重，答出来的就是旧规定。

### 2.3 截断与配额（`rag.py:273-278`）

- **相对截断 0.45**：低于首条 45% 的直接判噪声。绝对阈值在不同题型下不稳，相对值更耐变。
- **每篇最多留 2 块**：一篇办法里"类别"和"条件"常分在两段，只留 1 块必然答偏。
- **至少留 3 条**：首条判错时，后面的正确答案还有机会被看到。

### 2.4 分组排序：标题命中优先，档内比分数

同一文档的多个命中块合并成一条引用（`server.py` `_group_hits`）。
排序不是纯按分数，而是**先看标题二字命中，同档内再比分数**。

**为什么**：长文档靠"条件""要求"这类高频词能堆出虚高分。
问"转专页需要啥条件"时《学籍管理规定》拿 52.77 分，《转专业实施办法》只有 24.67 分、连前六都进不去——
用户看到的依据和系统真正该读的文件是两份。

### 2.5 召回宽度

| 链路 | 宽度 | 原因 |
|---|---|---|
| 问答 `/api/ask` | `top=12` 块 | 多意图长句会被单个文件的高频词吃满，6 块不够 |
| 关键词 `/api/keyword` | `top=48` 块 | 需要覆盖面，后面还要按文件聚合 |

**两条链路必须用同一条排序规则。** 否则点"关键词检索"和直接提问看到的首份文件不一样，出处就不可信了。

## 三、过滤规则（`server.py`）

### 3.1 文书类型：问制度就别端公示

`NON_RULE = 公示|名单|表彰|通报`（`server.py:1084`），命中即剔除。

**例外**：问题本身在要名单（`ASKING_LIST`，`server.py:1095`：名单/公示/谁获/获奖/获评/评上/几个名额/结果）时不剔除——
问"我评上了没"必须看公示。

**为什么**：获奖名单里没有"能不能办、要什么材料、什么条件"。它标题里"本科生""国家奖学金""申请"全有，
任何按分数算的判据都不觉得它弱。A1 就是被《2023 年国家奖学金推荐获奖学生名单的公示》硬接的。

### 3.2 适用对象：逐条比对，不做二值开关

文档侧判对象（`server.py:341-346`）：

| 类别 | 判据 |
|---|---|
| 研究生 | 研究生/硕士/博士/研一/研二/研三 |
| 本科生 | 本科/学士/专科/大一二三四/应届 |
| 教职工 | 教职工/教师/职工/辅导员/人才引进/职称/岗位聘任/干部 |
| 校级通用 | 两边都没写 → 两边都留 |

问题侧判对象，**只在明确冲突时剔除**。

**关键约定：`保研 / 推免 / 考研` 不算对象信号。** 那是本科生在问自己的升学路径，不是"我是研究生"。
旧版把"出现这些词就整体放行"，结果本科生问"补考没过重修咋收费 会不会影响保研"，
引用里混进《博士研究生招生管理办法》和《直博实施办法》。

**为什么不一律剔除跨对象文件**：校级通用文件（《学生管理规定》这类）标题没写"本科"，
但它含总则条款，扔掉就等于答不了。

### 3.3 专名缺口：语料里没有的词，不猜

`_gap_terms`（`server.py`）：问题里的 ASCII 专名（英文/数字/型号）在上下文里一次都没出现，就判拒答。

**为什么**：用户问"校园网 IPv6 怎么开通"，全库 0 个块含 IPv6，模型却照着"校园网"三个字编了 300 字开通流程。
这类词只可能是用户从别处听来的：语料里没有就是没有。只判 ASCII 专名，不动分数阈值。

## 四、拒答规则：五道闸

一道比一道靠后，能拦住的都会拦住。

| # | 闸门 | 条件 | 结果 |
|---|---|---|---|
| 1 | 实义字符不足 | 剥离后的实义汉字 < 2 个 | 直接空结果（`rag.py:249`） |
| 2 | 弱相关 | 首条 `score < 15`，或 `coverage < 0.55` 且标题只命中 1 字 | 拒答 + 建议问法（`WEAK_SCORE=15`，`server.py:981`） |
| 3 | 对象不匹配 | 问题与文档适用对象明确冲突 | 拒答 |
| 4 | 专名缺口 | 专名在上下文里 0 出现 | `mode=gap` 拒答 |
| 5 | 意图不匹配 | 外置规则判定证据不足（时间/班车/费用） | 拒答（`intent_rules.py`） |

**第 5 道为什么外置成规则文件**：按规则名特判的话，将来改个名行为就悄悄变了；
写成 `ask / require / evidence` 三个字段，改规则不用碰代码。

**模型侧还有最后一道**：语料里没有就直接输出 `【未收录】`（提示词第 3 条），
且**禁止反向推断**（第 12 条）——不能因为"没看到某条限制"就说"未把 XX 列为排除项"。
把"没看到"说成"没有规定"，学生按这句话去申请是要出事的。

拒答不是终点，**必须给可操作的替代问法**（`suggest()`），否则等于把用户丢在原地。

## 五、引用规则

- **定位三件套**：`doc_uid` + `chunk_id` + `sent_no`，前端显示"第 N 段 第 M 句"。
- **句号必须在整篇里定位**，不能拿"命中块拼接文本"数句号——那样算出的第 18 句在原文里可能不存在。
- **长文档固定带开头 2 块**：正文超过 8 段的文件，只喂命中块 ±2 会漏掉总则里的关键条款
  （《违纪处分规定》的"记过 10 个月"就在第 1 块）。
- **首屏引用要瘦身**：`_slim_cites` 去掉 `evidence`（每条 1–2KB），否则引用比正文晚到几百毫秒。

## 六、回答规则（`llm.py` 提示词 12 条）

| # | 规则 | 挡的是什么 |
|---|---|---|
| 1 | 第一句直接给结论 | 铺垫式开头等于没答 |
| 2 | 每条结论后标 `[编号]` | 无出处的结论不可复核 |
| 3 | 确实找不到才输出`【未收录】`，之后不再写任何内容 | 半拒半答最误导 |
| 4 | 金额、比例、时限、文号原样引用，不换算不概括 | 换算就是把 4.5 小时写成 4 小时 |
| 5 | 同事项以年份较新的为准；旧文件写明废止要指出 | 旧文长期不下架 |
| 6 | 默认本科生；两类规定并存优先答本科 | 用户主体是本科生 |
| 7 | 简体中文，≤400 字，不复述问题，不客套 | — |
| 8 | 只有定性规定时要明说"原文未写明具体数值" | 把"禁止大功率电器"答成"限 800W" |
| 9 | 资料按相关度排序，第 1 条能答就别拼凑 | 堆砌引用掩盖不确定 |
| 10 | 开头写出所问事项名称 | 分不清在答哪一问 |
| 11 | 多要素问题优先答前三项 | 要素太多时抓不住重点 |
| 12 | 禁止反向推断 | 把"没看到"说成"没有规定" |

## 七、地点规则（`places.py`）

地点问题走独立分支：先判意图是"在哪"还是"问别的"。

**只有问句带定位词（在哪/哪里/怎么走/位置/最近/路线/几号楼）才算已答。**
否则"食堂承包商是谁"会被当成"食堂在哪"，甩一串楼名——答非所问比拒答更伤人。

地点结果必须标数据来源（校园地图底座），并声明"开放时间、窗口办理以现场公示为准"——
地图底座不含营业时间，不说这句就是暗示自己知道。

## 八、流式协议（`/api/ask/stream`）

```
meta   → 引用先出（前端立刻能渲染出处）
delta  → 正文逐字增量（真流式，不插延时）
final  → 权威结果整体替换（含拒答与数值核对结论）
```

**缓存命中也必须走三段。** 任何按协议解析的客户端，面对"只吐一个 final"的服务都会判定它没有流式能力——
外部验收就这么判过一次。但**不许为了"看起来像流式"人为放慢**：缓存题本来就该秒出，
可以用分块，不能加 sleep。

## 九、相关问法（`related.py`）

答完之后推 3–4 条"你可能还想问"。**第一条规则是不许编题**：每一条在推出去之前，
都要过一遍和正常提问完全相同的检索链路（文书过滤 + 对象过滤），过了才留下。
点了问不出东西的推荐，比不推荐更伤人。

门槛比整句提问松一档——短题命中的词少，BM25 项就少，分数天然低：

| 判据 | 整句提问（`_weak`） | 相关问（`_answerable`） |
|---|---|---|
| 分数 | 低于 15 且标题命中 < 2 才算弱 | ≥ 15；或 ≥ 8 且覆盖率 ≥ 0.60 |
| 覆盖率 | 0.55 | ≥ 0.45（软档 0.60） |
| 话题 | 不看 | 话题词必须在**首条**里出现，且"标题里有"或"正文出现 ≥ 2 次" |

"休学怎么办"首条 9.2 分、覆盖率 1.00，命中的就是《学籍管理规定》——
按 15 分硬卡会把这类好题全毙掉，所以留了软档。反过来"勤工助学怎么申请"
首条是《助学贷款实施办法》、46 分，全文只在资助体系那段顺嘴提了一句
"勤工助学"，靠分数是拦不住的，靠"话题必须在首条出现两次以上"才拦住。

**族用来防话题漂移。** 问"转专业需要什么条件"，《转专业实施办法》正文里
出现两次"处分"、"两次"志愿"，只按词频推就会推出"处分多久能解除"。
所以能推哪些族（奖助/学籍/考试/纪律/生活/发展），由**问题本身命中的概念**和
**首条引用标题里的话题**一起决定，正文里顺带提到的一律不参与定族。

其余几条：

- **同一话题最多两条**，且只有问题里直接点名的那个话题才给两条。四条全说奖学金等于只推了一条。
- **不重复**：与刚才的问题二字切片 Jaccard ≥ 0.55 丢掉，与已入选的 ≥ 0.7 丢掉。
- **不推教职工文件**：问"病假要开什么证明"推过一道出自《后勤保障部人力资源管理暂行办法》的题，
  学生在那个文件里没有身份。
- **不调大模型、不联网**：一次 33–66ms、0 元。答案进缓存时推荐跟着进缓存，缓存命中照样能出。
- 推荐失败一律返回空表，不影响回答本身。

题面维护在 `related.py` 的两张表里：`CONCEPTS`（话题 → 学生问法）和
`FAMILY_POOL`（族内通用问法）。**加条目前先跑 `python related.py --check`**，
它会把 67 道题逐条过一遍检索，答不上来的标 × ——过不了的别硬留。

## 十、回归与验收规则（`tools/regress.py`）

两层分开统计，因为它们会独立退化：

| 层 | 判据 | 抓的是 |
|---|---|---|
| 检索层 | 首条命中文档的标题是否含期望词 | 检索跑偏 |
| 问答层 | 答案前**两条**引用里是否有一条命中 | 答错但看起来对 |

- **两条而不是一条**：答案里标 `[2]` 是常态，首位文件常是"相邻但相关"的。
- **首条是公示/名单/表彰即判 FAIL**：这类文书里没有条款，命中不等于答对。
- **期望是可以写错的**：`D3` 研究生出国交流在三份语料里都是 0 篇，原期望"应命中"等于要求它编；
  `B5` 2026 放假通知一度被我误判成 0 篇而改成应拒答，复查发现它在 `web_chunks.jsonl` 里，已回滚。
  **改期望前必须查全三份语料**：`chunks.jsonl` + `web_chunks.jsonl` + `facts_chunks.jsonl`。

`eval.py` 是日常问法的防退化套件，`regress.py` 才是会掉分的那套。两套题难易不同，**别把两者的数字混着比**。

## 十一、维护规则

1. **加语料走三份文件**，只改 `docs_final.jsonl` 不会生效——服务加载的是 `chunks.jsonl`。
2. **改阈值前先跑一遍两层回归**，记下改动前后的数字。没有 before/after 的调参是在猜。
3. **不要用纯文本判定代替语义判断**：`/api/keyword` 没有语义能力，它剩下的 FAIL 靠阈值改不动，
   需要条款级索引或重排模型——知道边界在哪，比反复调参数省事。
4. **发布用 tag 标里程碑**，见 `docs/VERSIONS.md`；不复制目录做"版本备份"。
5. **改完语料点一次「更新文件库」**（`POST /api/rebuild`）：重新读 `corpus/` 下的三份文件、
   重建 BM25 索引、清空答案缓存，返回真实的增删数量与耗时（约 0.8 秒，3180 块）。
   语料改了但没人点，服务内存里还是旧的；这一步只是省掉重启进程。
   左下角「语料更新于」取的是三份文件的 mtime，不是打开页面的时间。
6. **别把"看起来在工作"当成在工作。** 这个按钮在 2026-11-02 之前是假的：四段 CSS 动画走 2.5 秒，
   从头到尾没发过一个请求，末尾那句「已是最新 · 620 份文件，无需更新」是写死的。
   判别方法很简单——点一下，看 DevTools 的网络面板有没有请求；没有，就是动画。
